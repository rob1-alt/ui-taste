    How Claude uses it

    Four steps, every time it builds or reviews an interface.

    1. 01

      Inspect

      Read the project's own system first. The project always wins over any reference; if there is no system, the skill writes one down before building on it.

      DESIGN.mdtailwind.config.tsglobals.csscomponents/ui/
    2. 02

      Reference

      Search the library only to settle a concrete question. One strong screen is enough, three is the limit, and Claude opens the screenshot before it decides.

      “linear pricing” → plain columns, one filled button
    3. 03

      Build

      Apply the decision with the project's components and tokens: one type family, a real scale, neutral surfaces and one accent, real content only.

      AaAaAa
    4. 04

      Review

      Render at 1440 and 390 pixels, look at the result, run the checklist below and fix what it finds. A screen nobody looked at is not reviewed.

      1440390
