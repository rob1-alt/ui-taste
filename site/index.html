§3Method

What the skill makes Claude do, every time it touches an interface.

3.1Inspect

Read the project's own system first: a DESIGN.md, tokens, the Tailwind config, the component library, the two or three screens closest to the one to build. The project wins over any reference. If there is no system, the skill writes one down before building on it.

3.2Reference

Search the library only to settle a concrete question: how dense a pricing table should be, how a changelog entry is laid out, what a dark hero needs to stay readable. One strong screen is enough, three is the maximum. Claude opens the screenshot and looks at it; it does not guess from the description.

3.3Build

Apply the decision with the project's components and tokens. One typeface family, two at most. A type scale with real steps. Neutral surfaces and one accent, used for action and state. One radius family. Real content only: no invented customers, numbers or testimonials.

3.4Review

Render the screen at 1440 and 390 pixels, look at it, and go through the checklist in §4. Report what was checked and what changed. A screen that was never looked at is not reviewed.

§4Review

The list Claude goes through on the rendered screen. Each item is a pattern that makes an interface read as generated. This page was checked against it too.

§5Install

Two commands in Claude Code. Then ask for a pricing page, a dashboard that looks generic, or a design system for a project that has none.
